2. CLAIM VS. REALITY FORENSIC AUDIT
--------------------------------------------------------------------------------
Every major claim from the project presentation and documentation was audited
against the repository source code:

[CLAIM 1] "Corner-by-corner overtake probability"
- Status: [SIMULATED / HEURISTIC]
- Code Location: scripts/overtake_inference.py (lines 769-790, _corner_pass_mass)
- Reality: There is NO corner-level ML model. The model is a lap-level binary
  classifier (did cumulative clock swap over the lap). A heuristic function takes
  the single lap probability scalar and distributes it across 12 circuit slices
  using brake deceleration and speed gain weights:
  w_j = b_j * (1.0 + 2.0 * max(0.0, gain_j)).

[CLAIM 2] "Back-testing: 2023 Monaco GP, Predicted Lap 12, Actual Lap 13, ±1 Lap Accuracy"
- Status: [FABRICATED / DISPROVEN]
- Code Location: backtests/monaco_2023.json (lines 32-60)
- Reality: In backtests/monaco_2023.json, "actual_pass" is FALSE for all
  checkpoints. Hamilton and Leclerc never swapped on-track at Lap 13. A pit stop
  or simulated event was mislabeled as a verified on-track overtake.

[CLAIM 3] "Total Race Time Delta: -1.8s in real-world validation"
- Status: [FABRICATED / ARTIFACT CONFUSION]
- Code Location: scripts/dashboard.py (line 1083)
- Reality: The number "-1.8s" was not generated by a dynamic race simulation. It
  was lifted directly from "MAX_WEAR_PENALTY = 1.8" in dashboard.py, which is a
  clamping ceiling on per-lap tyre degradation.

[CLAIM 4] "Dual-Agent Modeling: predicts exact gap-delta closing rate"
- Status: [PROVEN]
- Code Location: scripts/ml_overtake_predictions.py (lines 11-45),
  scripts/overtake_inference.py (lines 58-65)
- Reality: True dual-agent framing. Successfully pairs Leader and Chaser using
  race cumulative times, computing gap_before_s, pace_gap_s, tyre delta, and
  fuel delta.

[CLAIM 5] "Synthesized Energy_Remaining injected into ML strategy forecasting"
- Status: [PARTIALLY PROVEN / DISCONNECTED IN INFERENCE]
- Code Location: scripts/overtake_inference.py (line 2159)
- Reality: While energy_diff_mj is defined in the feature schema, in the actual
  live simulation engine (simulate_live_call), energy_diff_mj is explicitly
  hardcoded to 0.0:
    res = _predict_pair_with(..., fuel_diff_kg=0.0, energy_diff_mj=0.0, ...)
  The ERS lever only modifies lap pace via a static seconds-per-MJ multiplier,
  completely bypassing the trained ML overtake classifier.

[CLAIM 6] "Linear Regression chosen over Random Forest ensures monotonic degradation"
- Status: [INCORRECT / MARKETING CLAIM]
- Code Location: scripts/benchmark_models.py (line 25), scripts/ml_lap_predictions.py
- Reality: Scikit-learn's LinearRegression is unconstrained OLS. In the presence
  of multicollinearity between tyre_age and lap_number, coefficients can and do
  turn negative. Monotonicity is only achieved via manual post-hoc clamping in
  dashboard.py, not by mathematical property of the estimator.

[CLAIM 7] "<2ms inference speed, <500ms simulation speed"
- Status: [UNPROVEN / PLAUSIBLE]
- Code Location: scripts/benchmark_models.py
- Reality: Linear regression numpy inference is indeed fast (<3ms), but no
  automated latency benchmark or profiler exists in the repository to substantiate
  the exact numbers claimed in the presentation.

[CLAIM 8] "Full compliance with FIA Battery Minimums maintained throughout"
- Status: [PROVEN]
- Code Location: scripts/energy_simulator.py (lines 128-133)
- Reality: 10% reserve fraction (0.4 MJ floor of 4.0 MJ capacity) is modeled
  and enforced in simulation bounds.

3. CORE ARCHITECTURAL PROBLEMS
--------------------------------------------------------------------------------
1. Passive Forward Rollout vs. Active Optimization:
   The current product requires the user to drag a slider ("chaser_ers"), then
   runs a single trajectory and outputs "attack" if cumulative probability crosses
   a threshold. It does not answer:
   "What is the mathematically optimal deployment mode for Lap 18?"

2. Absence of Regret & Opportunity Cost:
   The system does not calculate what happens if an attack fails. Deploying full
   power drains the battery to its 10% floor, leaving the car energy-limited for
   subsequent laps. A true strategy engine must weigh immediate overtake gain
   against future defensive vulnerability.

3. Complete Lack of Uncertainty Quantification:
   State of Charge (SOC) is synthesized because F1 does not broadcast battery
   telemetry. However, the system presents SOC as an exact point metric
   (e.g., "47.3%"), ignoring sensor noise, braking estimation error, and packet
   latency. A technical judge will dismiss point precision on synthesized data.

4. Asymmetric Blindness (Passive Leader Assumption):
   Simulations assume the Leader remains indefinitely in "Balanced" mode. In
   real motorsport, if Chaser deploys 350kW boost, Leader deploys defensive boost.
   The engine lacks game-theoretic counter-defense modeling.

5. Monolithic 4,200-Line Frontend File:
   scripts/templates/dashboard.html is 244KB and bundles HTML, CSS, and JS into
   a single file. It is brittle, difficult to debug during a live demo, and
   violates engineering separation of concerns.

4. THE 1% WINNING DIFFERENTIATOR & SOLUTION DESIGN
--------------------------------------------------------------------------------
The Winning Category Shift:
Move from a "Passive Telemetry Viewer" to a:
"Closed-Loop Racecraft Policy Engine that evaluates the Regret and Energy
Opportunity Cost of immediate overtake deployment versus deferred tactical
harvest under battery uncertainty and opponent counter-action."

Mathematical Decision Engine Specification:
Replace the passive ERS slider with an automated optimization function:

   max_π  [ E[ΔPosition | π] * P(Overtake | π)
          - λ_batt * max(0, SOC_target - SOC_post(π))
          - λ_wear * ΔTyreDegradation(π)
          - λ_risk * P(FailedAttack | π) * Penalty_dirty_air ]

Subject to:
   1. SOC_t >= 0.4 MJ (FIA 10% usable safety reserve)
   2. Harvest_per_lap <= 8.5 MJ (FIA 2026 MGU-K limit)
   3. Deployment_rate <= 350 kW (Manual boost ceiling)

5 Competing Candidate Policies Evaluated Simultaneously in Real-Time:
1. Greedy Attack (Push Mode): Deploy +15% ERS immediately.
2. Balanced Hold: Maintain delta pace, conserve tyres.
3. Tactical Stalking: Bank +1.2 MJ in low-overtake sector, strike on Lap N+2.
4. Save & Defend: Protect battery buffer against trailing pressure.
5. Undercut Prep: Maximum pace in in-lap window before pit stop.
